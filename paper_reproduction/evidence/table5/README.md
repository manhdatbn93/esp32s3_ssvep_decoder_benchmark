# Table 5 records

Table 5 is a representative pre-release resource snapshot. Every one of its 73 numeric values (44 footprint, 29 runtime memory) is transcribed from a file in this directory and is regenerated by `paper_reproduction/reproduce.py`. The four `---` arena cells are the analytical backends, which allocate no TFLite Micro arena.

These records were not produced by the firmware image that generated the strict LOSO replay in `../replay/`.

| | Table 5 snapshot | Strict LOSO replay |
| --- | --- | --- |
| Dates | 16–17 Apr 2026 (footprint, heap, stack); 26 Apr 2026 (arena) | 23–24 May 2026 |
| Firmware | Uncommitted pre-release `replay_fw` for footprint, heap, and stack; `smoke_fw` for the arena | `replay_fw` commit `31fb64b` |
| Models | Fold-1 models of an earlier subject-as-validation protocol (held-out subject s1) | Strict LOSO fold models, one per test subject |
| Sessions | One profiled replay session (subject s1, 180 trials) or one smoke run per backend | 10 subjects × 180 trials per backend |

For all seven neural backends, the fold-1 models in this snapshot have the same byte size, tensor shapes, data types, quantization-parameter counts, operator list, and operator wiring as the strict fold models of all 10 folds. That match supports reading the embedded-model bytes and the TFLM arena plan as representative of those graphs. It does not make the April heap drop or stack high-water a measurement of the May strict-LOSO firmware. Those two quantities also depend on the unarchived April build configuration and on other tasks in the session, including Wi-Fi. CCNN-int8 and FBtCNN-int8 were re-exported after 17 Apr 2026 with unchanged size and structure, so their April footprint, heap, and stack describe that predecessor, not the May image.

Latency is never taken from this snapshot. All latency values come from `../replay/`.

## Files

`reproduce.py` reads the transcription, the UART session summaries, and the arena log.

| Path | What it records |
| --- | --- |
| `idf_size_screenshots/<backend>.png` | `idf.py size` screenshot. Flash and static DRAM come from the total row. |
| `idf_size_transcription.csv` | Byte transcription of those 11 screenshots. |
| `uart_replay_sessions/uart_<backend>.log` | UART log of the profiled session. |
| `uart_replay_sessions/uart_<backend>_profile.txt` | `RES_PROFILE phase=session_summary` block from the same session. ConvCA uses `uart_convca_f32_profile.txt`. |
| `smoke_arena/tensor_arenatxt.txt` | `TFLM_ARENA backend=... cap=... used=... region=PSRAM` lines from the seven smoke runs. |

The public copy of `idf_size_screenshots/eegnet_f32.png` has its top 40 pixel rows painted over. The build header showed a local path. Pixels below that band are unchanged. The April `sdkconfig` was not archived, so CPU frequency and compiler optimization for this snapshot are not verified. The screenshots are the only footprint record.

KiB values are bytes/1024, rounded half-up to one decimal place.

## Heap drop

On the `RES_PROFILE phase=session_summary` line:

```text
sess_est_peak_drop_int = sess_baseline_int - sess_min_int
```

`sess_baseline_int` is the internal free heap at `pre_backend_init`. `sess_min_int` is the lowest internal free heap sampled from that point through the last successful forward. The difference is a session-scoped lower bound on transient internal consumption. It is not a hardware memory tracer, it does not isolate Wi-Fi or other tasks, and it is not the boot-wide minimum (`int_min_ever_boot`).

## Stack high-water

`stack_hwm_words` is the field name in the UART record. The value is `uxTaskGetStackHighWaterMark(NULL)` for the `replay_tcp` task. On ESP-IDF for the ESP32-S3 that call returns unused stack in bytes at the deepest use, not FreeRTOS words. It is the minimum free stack of that task, compared with the configured `REPLAY_TCP_STACK_BYTES` of 16 KiB. It is not a stack measurement for the whole firmware image. For the analytical backends it is a lower bound on remaining headroom in that 16 KiB stack.

## Arena

Neural rows use `used` and `cap` from the `TFLM_ARENA` lines. All seven arenas were allocated in PSRAM. The capacities, which are not printed in the submitted table, are CCNN-f32 and CCNN-int8 512 KiB, ConvCA-f32 512 KiB, EEGNet-f32 256 KiB, EEGNet-int8 384 KiB, and FBtCNN-f32 and FBtCNN-int8 768 KiB. The submitted table prints the used size.

## Limits

- Each value comes from one build and one session per backend. There are no repeats.
- Rebuilding the current firmware does not reproduce these byte counts. The application image embeds the build time, and a new compile is not a Table 5 measurement.
